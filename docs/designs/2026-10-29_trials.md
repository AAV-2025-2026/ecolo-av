# Trials: new controllers and localizers beside the main ones

* **Author:** Ben (the ask), written up 29 Oct 2026
* **Status:** Proposed (EGM review below, then build)

Ben, 29 Oct: "Just directories for each idea all in the ros directory. We want to test it
as part of the full project. We want to see what the advantages are of MPPI, pure follow,
mpc, lqr, partical, etc." And: "We don't completely want to replace other work. We want to
make other nodes or plugins that we can test and then replace the main ones if they work."

## The idea in one line

Each idea is **its own ROS package** under `ros/`, built and tested with everything else.
It runs **beside** today's default, chosen at launch, and is **scored on the same routes**.
It becomes the default only once it wins.

## What is on trial

| Trial | Against | Package | Chosen by |

MPPI and Regulated Pure Pursuit stay as they are: Nav2's `controller:=mppi|rpp`.

## The shape

```
                 goal (map x, y, heading)
                        │
         ┌──────────────┴──────────────┐
         ▼                             ▼
   Nav2 (today)                  aav_track (new): one driver node
   planner + MPPI or RPP          1. asks Nav2's planner for a path (Smac Hybrid-A*)
         │                        2. follows it with the chosen tracker:
         │                           pure_pursuit | stanley | lqr | mpc
         │                        3. speed from approach.py (speed up, hold, stop)
         ▼                             ▼
  /drivers/nav/cmd_vel          /drivers/track/cmd_vel
   (twist_mux 20)                (twist_mux 22: above Nav2, below drive-to-point)
         └──────────────┬──────────────┘
                        ▼
              twist_mux → ego → backend (unchanged)
```

- **One node, many trackers:** `ros/control/aav_track` holds the node: goals, the path, speed,
  safety stops (reusing `aav_drive_to_point`'s `rules.py` and `approach.py`). Each tracker's
  maths is its own package with no ROS (CLAUDE.md: keep the maths out of ROS), the same small
  interface: `steer(pose, speed, path) -> steering angle`, plus its own tests.
- **The path:** Nav2's `planner_server` action `compute_path_to_pose` (planner only; Nav2's
  controller is not asked). Same planner as MPPI, so a comparison tests only the follower.
- **Obstacles:** the trackers follow the path; they don't read the costmap. They replan
  every 2 s (as Nav2 does) and collision_monitor still stops the car. So they are compared
  on the lot tour; on the obstacle tour they are scored only on "did it stop".
- **Speeds:** TwistStamped (v, ω = v·κ), as every driver (CLAUDE.md "Commands").
  κ = tan(δ)/wheelbase from the tracker's steering angle δ.

## Localization trials

| | AMCL | NDT |
|---|---|---|
| Reads | `/sensors/lidar/scan` (2D) and a 2D map | `/sensors/lidar/points` (3D) and a 3D map |
| Map from | the sim's map (`map_server`); on the car, `slam_toolbox` | KISS-ICP over a bag of the lot |
| Gives | a pose with covariance | a pose with covariance |
| Into | compared only, then optionally `ekf_global` as a pose input | the same |
| Package | stock `nav2_amcl`, our config and launch | ours, Rust (nalgebra, kiddo, argmin) |
| When | now (Gazebo) | after AMCL, and after a lidar bag from the lot |

A trial localizer **never** publishes TF on its first run: it publishes
`/localization/<name>/pose`, and a comparison tool scores it against Gazebo's truth and the
EKF. Feeding the EKF is a second, separate step, once it scores well.

## Scoring

| Tool | Scores | Change |
|---|---|---|
| `controller-compare` | path followers on the lot tour | `--controllers rpp,mppi,pure_pursuit,stanley,lqr,mpc` |
| `atob-score` | speed up, hold, stop on B | unchanged |
| `localization-compare` (new) | pose error vs truth, parked and driving | new, `tools/` |

Each run writes its tables into `docs/trials.md` by hand, with the date and the commit:
what won, by how much, on which world.

## Order

1. `aav_track` + pure pursuit (the baseline, same as `aav_drive_to_point`'s): proves the
   frame, with no new maths.
2. Stanley and LQR (small, from `vehicle_model.lateral()` for LQR).
3. MPC: Python first with scipy, for the comparison; Rust (Clarabel) once it wins.
4. AMCL and `localization-compare`.
5. NDT: needs a map; design separately.

## Not in this

- Replacing MPPI on the obstacle tours.
- Any change to the safety path: twist_mux's locks, collision_monitor, the spine.
- The car: every trial is Gazebo-first; on the car only after it wins in Gazebo.
