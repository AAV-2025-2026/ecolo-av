The rule

The first part of every name is the area: the layer of the picture it comes from. The same areas as the folders under src/.

/<area>/<device or node>/<thing>
Area Holds Who publishes
/sensors/ raw sensor data the drivers on the Pis and the Orins
/vehicle/ what the car says about itself the backend (spine, legacy, Gazebo, bench)
/can/ raw CAN frames the socketcan bridge
/localization/ where the car is the EKFs, navsat_transform
/perception/ what the car sees the detectors, the lane finder, radar clusters
/drivers/ one command per driver joystick, keyboard, scripted, Nav2, AI, replay
/control/ the chosen command twist_mux, the smoother
/ego/ the command for the wheels ego
/safety/ e-stop, collision monitor the HUD button, collision_monitor
/hud/ what only the screen needs the HUD

Global names stay global, because every ROS tool expects them: /tf, /tf_static, /clock, /robot_description, /joint_states, /diagnostics, /rosout. Nav2 keeps its own names (/plan, /goal_pose, its actions) for now.

How we would do it

  1. Change docs/interfaces.yaml first (the contract), and regenerate interfaces.md.
  2. Rename in the launch files and configs with remaps: most stock nodes (robot_localization, ublox, twist_mux) take a remap, not a code change.
  3. A test that checks every name in interfaces.yaml starts with an area from the table.
  4. pixi run check sim and bench-check must still pass.

Why the two EKFs don't talk

The local EKF doesn't feed the global one, and that is on purpose: robot_localization's standard setup. Each one fuses the raw sensors itself.

ekf_local ekf_global
Uses wheel speed, IMU wheel speed, IMU, GPS
Gives a smooth position that never jumps a true position that may jump
Publishes odom → base_link map → odom
Who uses it Nav2's controller (steering) Nav2's planner, the HUD's map

If the global EKF used the local one's output, the same wheel and IMU data would count twice, and it would be too sure of itself. Feeding both from the raw sensors avoids that.

They do meet, but in TF, not on a topic: ekf_global publishes only the correction map → odom, worked out on top of ekf_local's odom → base_link. So rqt_graph shows no line between them; ros2 run rqt_tf_tree rqt_tf_tree shows the chain. The launch file's first line said "the local EKF feeds the global EKF"; it now says this (14 Oct).
